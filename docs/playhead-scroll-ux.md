# UX: плейхед и горизонтальный скролл таймлайна

Документ фиксирует правила поведения **плейхеда** (линия текущего времени воспроизведения) и **скролла** дорожки в `tinysampler`. Реализация должна соответствовать этому описанию.

---

## Термины

- **Вьюпорт таймлайна** — видимый прямоугольник дорожки (не весь контент по времени).
- **Плейхед** — вертикальная линия позиции `playhead_secs` (секунды от начала «мирового» времени проекта).
- **Скролл** — `timeline_scroll_px`: сдвиг «мира» в пикселях; время `t` рисуется на экране как `x = rect.left + t * px_per_sec - scroll`.
- **Якорь клика** — после seek скролл подбирается так, чтобы выбранное время оказалось **под указателем** в момент клика (без второго «догоняющего» движения в центр в том же кадре).

Положение плейхеда **относительно центра вьюпорта** (для классификации кейсов):

| Код | Смысл |
|-----|--------|
| **a** | Плейхед **левее** центра вьюпорта |
| **b** | Плейхед **правее** центра |
| **c** | Плейхед **в центре** (допускается небольшая зона ±ε из‑за округления) |

События:

| № | Событие |
|---|--------|
| **1** | Play (старт / возобновление воспроизведения) |
| **2** | Pause |
| **3** | Stop |
| **4** | Клик по дорожке или клипу (seek) |

---

## Общие принципы

1. **Нет snap-to-center во время Play** — не подгоняем скролл так, чтобы плейхед каждый кадр оказывался строго по центру вьюпорта (это вызывало визуальный «прыжок» после seek).
2. **Stop (3)** — сброс воспроизведения: время в начало, **скролл в 0**, снятие отложенных seek-флагов (как в коде).
3. **Pause (2)** — **заморозка**: скролл и картинка не двигаются от транспорта; положение плейхеда на экране остаётся до следующего Play / seek / Stop.
4. **Play (1)** — в кадре нажатия **не** делаем принудительного перескролла «подогнать под центр»; дальше при воспроизведении действует только правило краёв (см. ниже).
5. **Клик (4)** — всегда **seek** + **якорь скролла** под курсор (и при Play, и при Pause).

## Матрица кейсов (целевое поведение)

| Кейс | Условие | Поведение |
|------|---------|------------|
| **a1** | Левее центра + **Play** | Не центрировать; скролл в кадре Play не менять; плейхед движется вправо вместе со временем. |
| **a2** | Левее центра + **Pause** | Не скроллить, не отцентровывать. |
| **a3** | Левее центра + **Stop** | Как глобальный Stop: время 0, скролл 0. |
| **a4** | Левее центра + **Клик** | Seek + якорь скролла под курсор. |
| **b1** | Правее центра + **Play** | Аналогично **a1** (без snap-to-center). |
| **b2** | Правее центра + **Pause** | Аналогично **a2**. |
| **b3** | Правее центра + **Stop** | Аналогично **a3**. |
| **b4** | Правее центра + **Клик** | Аналогично **a4**. |
| **c1** | В центре + **Play** | Не вводить лишнего скролла в кадре нажатия; дальше — правило краёв. |
| **c2** | В центре + **Pause** | Аналогично **a2**. |
| **c3** | В центре + **Stop** | Аналогично **a3**. |
| **c4** | В центре + **Клик** | Seek + якорь (плейхед часто уйдёт от центра — ожидаемо). |

## Правило краёв во время воспроизведения

Пока **идёт Play**, если плейхед оказывается ближе к **левому** или **правому** краю вьюпорта, чем **отступ** (margin), скролл **минимально** сдвигается, чтобы плейхед остался внутри «безопасной» полосы.

Параметры в коде:

- Константа `PLAYHEAD_EDGE_MARGIN_PX` (базово 48 px), на практике ограничивается `min(15% ширины вьюпорта, margin)` и не ниже ~20 px (см. `scroll_keep_playhead_in_view` в `app.rs`).

Цель: без постоянного центрирования плейхед **не уезжает за край** экрана при длинном воспроизведении.

---

## Масштаб (px / sec)

- **Ctrl + колёсико** над таймлайном меняет масштаб в диапазоне `TIMELINE_PPS_MIN` … `TIMELINE_PPS_MAX`.
- При смене масштаба сохраняется **время под курсором** (якорь масштабирования), см. логику zoom в `app.rs`.

## Связь с кодом

| Механика | Где смотреть |
|----------|----------------|
| Якорь seek по клику | `app.rs`: обработка `timeline_bg.clicked()` и клика по клипу |
| Правило краёв при Play | `TinySamplerApp::scroll_keep_playhead_in_view` |
| Скролл / константы | `timeline_scroll_px`, `PLAYHEAD_EDGE_MARGIN_PX`, `TIMELINE_PPS_*` |
| Время плейхеда в аудио | `audio.rs` + атомарный seek из UI |

При изменении поведения **сначала** обновить этот документ, затем код (или наоборот — но документ и код должны совпадать).
